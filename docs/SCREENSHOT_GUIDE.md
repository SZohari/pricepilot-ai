# Screenshot Guide

Recommended screenshots for a portfolio case study or project README:

| Screenshot | What To Show | Suggested Caption |
| --- | --- | --- |
| Main recommendations dashboard | Processed Real Market Dataset selected, KPI cards, filtered recommendations table, and action/risk display | Explainable recommendations for smartwatch products under local market volatility |
| Strategy price details | A product detail view showing the six strategy prices and selected recommendation | Multiple retail strategies presented for human review |
| Market Update console | Product selection, source links, readable market price fields, and toman/rial preview | Assisted daily market-price capture with Iran-friendly number formatting |
| Add New Product form | Catalog, store data, and global reference sections populated with demo-safe values | Adding a new wearable product without editing CSV files |
| Our Store Data update | Existing product selected with current values and editable price, inventory, margin, and strategy fields | Seller-owned operating data maintained from the dashboard |
| Build pipeline success | Successful **Run Build Pipeline** result in the UI, or terminal build output beside the dashboard | Raw observations and updates rebuilt into a processed recommendation dataset |
| Test results | Terminal output showing the complete `pytest` run passing | Automated coverage for data entry, pipeline behavior, and recommendation safety |

## Capture Notes

- Use sample or intentionally anonymized demo values only.
- Prefer the **Processed Real Market Dataset** mode when showing connected workflow behavior.
- Include one readable high-value toman entry and its rial equivalent preview.
- Keep the browser width large enough that tables and price cards are legible.
- Avoid displaying private source URLs, internal costs, or operational notes if publishing publicly.

## Suggested Sequence

1. Main dashboard overview
2. Strategy details for one product
3. Add New Product form
4. Our Store Data editor
5. Market Update and FX entry
6. Build success confirmation
7. Passing tests
